# 周节奏与批量分解

2026-10-30。替代上一版武器数值与逐把分解交互，仍然只有祈器、分解兑换两个玩法。

## 目标与口径

每天产生 500 万至 1000 万 Token，以中位 750 万校准。全部可用 Token 用于抽取、保留全部仙品、分解全部非仙品、材料只兑换仙品时，长期平均约一周获得一把仙品。每一把随机抽到或材料兑换的仙品均计作一次获得，不把仙品本身再次分解计算收益。

这是长期产出率，不是首周必得，也不是让不同用量的人固定每周领取。囤 Token、保留其他武器或兑换其他档位，会降低这个速度。兑换不重置随机抽取保底。

## 参数

单抽 100,000 Token，十连 1,000,000 Token。每天对应 50–100 抽。

| 品级 | 基础概率 | 每把分解 | 定向兑换 |
| --- | ---: | ---: | ---: |
| 凡品 | 75% | 1 | 12 |
| 良品 | 20% | 3 | 36 |
| 上品 | 4.5% | 8 | 120 |
| 极品 | 0.4% | 25 | 400 |
| 仙品 | 0.1% | 100 | 6,000 |

材料单位均为玄铁。每档 3 把，档内等概率。参数的唯一运行时定义位于 `packages/shared/src/weapons.ts`，界面价格和概率直接读取，不另写常量。

- 连续 19 抽未出上品及以上，第 20 抽将凡/良品提升至上品，自然高品级结果不降低。
- 连续 999 抽未出仙品，第 1000 抽必出仙品，优先于上品保底。
- 提前抽到重置相应计数，单抽、十连共享；无软保底、隐藏概率或日历奖励。
- 1000 抽硬保底对应 1 亿 Token，并不承诺每周必得。每天 750 万时，最长连续无随机仙品约 13.3 天。

## 模拟与校验

`apps/server/src/companion/forge.test.ts` 使用真实抽取规则、固定种子 123456789，模拟 5,000,000 抽；测试同时约束概率排序、最大保底间隔和综合周期在 6.8–7.2 天之间。

| 品级 | 数量 | 含保底实际占比 |
| --- | ---: | ---: |
| 凡品 | 3,636,954 | 72.7391% |
| 良品 | 971,506 | 19.4301% |
| 上品 | 363,699 | 7.2740% |
| 极品 | 19,960 | 0.3992% |
| 仙品 | 7,881 | 0.1576% |

非仙品平均每抽回收 1.9920128 玄铁，总材料可另外兑换 1,660 把仙品。合计 9,541 把仙品，平均每把消耗约 52,405,408 Token（524.05 抽）。仙品不参与回收，保留的余料不算成完整武器。

| 每日 Token | 综合长期平均周期 |
| --- | ---: |
| 500 万 | 10.48 天 / 把 |
| 750 万 | 6.99 天 / 把 |
| 1000 万 | 5.24 天 / 把 |

只计抽取，模拟平均 634.44 抽一把；从零材料开始，第一把主要靠随机与保底，约 8.46 天（750 万/天），不是 6.99 天的周发奖。理论截断几何分布均值 `(1 - (1 - 0.001)^1000) / 0.001` 约 632.3 抽，与模拟接近。

材料兑换是慢速的定向积累，而非每天额外发放仙品。平均约 3012 抽非仙品回收量可换指定仙品；选择保留部分武器时更慢。所有档位兑换价格高于分解产出，不存在兑换再分解的收益循环。

## 批量分解交互

- 默认浏览没有复选框；点击图片选择兑换目标。通过「批量分解」按钮进入选择模式，选中卡片变暗并显示勾，无库存禁用。
- 选择模式才提供全选与品质菜单：仅凡品、凡品加良品、凡品加良品加上品。退出或完成后返回普通浏览，无默认选择。
- 单击切换选择；长按 350 毫秒后拖动，按起点状态连续选择或取消。快速跨越通过线段与卡片矩形求交避免漏选，同一笔重复经过只处理一次；短暂滑动不启动选择，指针取消或失去捕获不额外触发单击。Esc 取消确认或退出选择。
- 选中一个种类代表分解其全部持有数量，包括最后一把；不再逐项输入数量。
- 按钮显示总把数和总玄铁，确认条再次展示种类、把数和材料。含仙品时额外标出。
- 取消不改变库存，成功后清空勾选；无默认勾选、不自动分解。分解动画只作用于实际处理的武器。

十连改为更宽的填色主按钮，单抽为描边次按钮。价格及 Token 汇总采用 K / M / B，显示边界会进位（如 999950 显示 1M），悬停提供精确值；经济参数和真实扣费不变。

## 原子性与旧档

新增 `dismantleBatch` IPC，经相同已知主窗口校验和采集器串行队列处理。接受 1–15 个不重复的武器 ID，以确认时 revision 锁定整个库存快照；全部校验、计算回收量后一次移除并保存。任意无效项、版本冲突、数字溢出或落盘失败，整批不生效。

请求 ID 和排序后的 ID 集合共同去重，调整选择顺序不会使重试重复结算。保存最多 15 种武器的回执，总数量独立记录。取消或修改勾选会撤销确认，收到新版交易状态也会撤销旧确认。

兼容已有 schemaVersion 2，不重置库存、材料、余额、已消费量或保底计数；只扩展新保底计数上限及批量回执长度。旧版的廉价武器不追缴，不重新发放 Token。原单项分解接口仅保留兼容，不再是当前界面流程。

本次验证结果：162 项测试、类型检查、构建通过。源码及重新解压的 Windows ZIP 原生流程通过；发行包在隔离 Node 搜索路径、150% 显示缩放下验证，无 HTTP 请求、无未捕获页面错误，默认与紧凑窗口无需滚动。宿主临时使用禁用 Chromium 沙箱/GPU 参数，未写入发行代码；独立干净机器默认启动仍待人工验收。
