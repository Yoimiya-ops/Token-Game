# 修仙版游戏界面设计

## 目标

把当前 Token Game 的游戏窗口从“喂猫数据面板”改成“桌面修仙洞府”。玩家启动后先看到桌宠，双击进入游戏窗口后，会进入一个以修炼、种田、打坐、炼丹为核心的养成界面。

## 核心体验

- 游戏窗口保持桌面工具式密度，但主题统一成修仙世界。
- `天机读取` 作为全局加载体验，用于启动、同步、切页和关键动作反馈。
- TokenTracker 继续作为真实输入源，但前台不再强调 token 术语，而是把它包装成“天机”“灵气”或“外界气运”。
- 主界面围绕四个主功能展开：修炼、种田、打坐、炼丹。

## 玩法概念

### 资源

- `修为`：主成长值，用于境界推进。
- `灵气`：通用行动能量，来自 TokenTracker 同步和部分行动。
- `灵石`：通用货币，用于基础消耗和部分升级。
- `灵草`：种田产出和炼丹材料。
- `丹药`：突破和增益道具。

### 功能

- `修炼`：消耗灵气，把灵气转为修为。
- `种田`：经营灵田，稳定产出灵草和少量灵石。
- `打坐`：低操作挂机页，稳定产出少量灵气和修为。
- `炼丹`：消耗灵草与灵石，产出丹药和突破材料。

### 加载文案

统一使用“天机读取”风格：

- `正在读取天机……`
- `正在引灵入体……`
- `正在唤醒灵田阵法……`
- `正在预热丹炉……`
- `正在铺开蒲团……`

## 界面结构

### 顶部状态栏

- 洞府名
- 当前境界
- 当日天机入账
- 当前资源摘要
- 当前页面标签

### 左侧角色区

- 角色立绘或头像
- 当前状态：修炼 / 种田 / 打坐 / 炼丹
- 境界条
- 当前加成或异常状态

### 中央主操作区

- 默认进入 `修炼`
- 用分页切换 `修炼`、`种田`、`打坐`、`炼丹`
- 每页保留一个主 CTA 和若干次级信息块

### 右侧资源区

- 灵气、灵石、灵草、丹药、修为
- 今日收益
- 当前增益
- 快速动作

### 底部日志区

- 显示天机入账、收获、炼丹结果、突破提示
- 用较短的条目保持可扫读

## 风格

- 主题：国风修仙，偏仙侠经营。
- 色彩：深青、米白、暖金、朱砂点缀。
- 视觉：卷轴、玉简、丹炉、灵田、蒲团、符纹。
- 语气：克制、沉浸，不使用现代后台术语。

## 交互要求

- 单击桌宠只做互动，不直接进入游戏。
- 双击桌宠打开游戏。
- 切页和同步时先出现短暂的 `天机读取` 遮罩。
- 桌面窗口必须保持可拖动、可读、无横向滚动。
- 主要按钮要有明确主次，避免一屏塞满同权重按钮。

## 数据与逻辑

- 真实 token 同步仍由 TokenTracker 驱动。
- TokenTracker 数据到游戏资源的映射由服务端统一处理。
- 前端只消费归一化后的修仙状态，不直接解析 TokenTracker 队列。
- 游戏窗口展示的是修仙资源与行为结果，而不是原始 token 数据。

## 错误处理

- TokenTracker 不可用时，游戏仍可进入，只是天机入账暂停。
- 数据拉取失败时显示能恢复的错误状态，不阻塞整个窗口。
- 炼丹失败、资源不足、境界不足等情况要给出明确的短文案。
- 天机读取超时后自动退回到当前页面，避免黑屏。

## 测试策略

- 资源换算、升级公式、状态归一化使用纯函数测试。
- 游戏状态接口和动作接口用服务端测试覆盖。
- 修炼/种田/打坐/炼丹四个页面至少各有一个渲染或交互测试。
- 天机读取遮罩的显示与隐藏逻辑需要有单独测试。

## 非目标

- 不在这一版里做大型世界地图。
- 不在这一版里做多人联机或排行榜。
- 不在这一版里做复杂战斗系统。
- 不在这一版里替换桌宠启动器本体。
