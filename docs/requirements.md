# 需求文档

2026-10-29 极简 MVP 约定。旧版多角色与修仙经营需求以 Git 历史为准；本文件与当前聚宝盆方案一致。

## 产品目标

把正常使用 Codex 产生的 Token 汇聚成一座常驻桌面的修仙聚宝盆。极简、围绕 Token、离线本地，不鼓励额外烧 Token。

## R1 桌面产品

- 使用项目原有 Electron + React + Vite 技术栈。
- 玩家只接触透明聚宝盆与 Token 收获窗口两个界面。
- 本地文件加载、主进程内置采集、IPC 通信；不启动浏览器或 HTTP 服务。
- 首次启动展示两个窗口，后续只恢复聚宝盆；左键单击直接收取，右键或左键双击打开窗口，不混淆操作。
- 聚宝盆透明、无边框、置顶、可拖动，保存位置；通过托盘隐藏、显示与退出。
- 默认窗口主要信息与操作无需滚动，按屏幕工作区适配尺寸。

## R2 聚宝盆形象

- 主体就是修仙聚宝盆，不是猫或守着盆的角色。
- 使用专门的透明青玉聚宝盆素材，窗口与托盘图标统一；离线随包携带。
- 待机持续轻浮呼吸；新 Token 到达吸纳灵气；收取时回弹、碎光爆发、收入大字；空盆也有动作和明确 +0 提示。
- 无持续闪烁、声音、催促弹窗或常驻数字面板；悬停可看待收量。
- 无新用量不自动弹提示，支持系统减少动画偏好。

## R3 唯一 Token 循环

- 仅适配本机 Codex，仅计算总量，不区分 Token 类型。
- 新增自动采集并保存，第一笔即可收取，无门槛。
- 收获窗口显示待收、可用、今日与累计 Token，以及武器抽取和分解兑换。
- 收取把待收转入可用余额，不影响历史累计；期间新到达的用量留待下次。
- 不领取不扣累计、不衰减，不设置签到、任务、排行榜或消费目标。
- 目录缺失与格式异常在现有窗口内展示，目录选择使用系统对话框。

## R4 可靠存储

- 首次建立基线不灌入安装前历史，重启补采之后仍在的日志。
- 处理重复快照、分叉、归档、截断与半行；不确定时保留进度并报告错误。
- 采集游标与累计同一事务保存，保留备份；恢复失败不得静默清档。
- 旧档先备份，旧累计单独标注，不重新触发收获。
- 只读 Codex 日志，不保存对话正文或密钥，不修改真实用量文件。

## R5 分发

- 首发 Windows x64 完整便携 ZIP，内置 Electron、采集器、界面与素材。
- 不要求 Node.js、pnpm、Python、TokenTracker；用户正常安装使用 Codex 即可。
- 源码与包都以 Electron 验收，不能用浏览器截图替代桌面流程验收。
- 自动化覆盖计数、存档、两个窗口、IPC、拖动、收取、重启和窄窗口；独立干净机器等人工验收单独标注。

## R6 两个武器玩法

- 单抽 100,000 Token，十连同价合并；五档 15 把武器，公开概率、20 抽上品与 1000 抽仙品保底。计入分解兑换后，以每天 750 万 Token 长期平均约一周一把仙品为数值基准。
- 十连为突出主操作，单抽为次操作；价格、可用余额和 Token 统计用英文 K / M / B 缩写，完整数字保留在悬停提示中。
- 只抽武器，不混入货币、经验或其他奖品；抽取由主进程生成随机结果。
- 批量分解需主动进入选择模式，普通浏览不出现复选框或品质快捷选择。选中卡片变暗打勾，支持单击、长按拖选/取消、全选及凡/良/上品快捷选择；一次确认分解所选种类全部数量，展示总数量、材料和仙品风险，不自动分解。玄铁再兑换指定武器。
- 存档统一提交扣费、奖励、材料和保底；重复请求不重复收费，陈旧快照不能重复修改库存。
- v1 旧档备份后迁移，已收取 Token 只获得一次可用额度；旧 ledger 历史总量仍不冒充当前余额。

## 非目标

境界、等级、经验、武器穿戴属性、强化、战斗、其他掉落、多个角色、自定义形象、其他 Agent、硬件、账号、联网排行、防作弊、自动更新。
